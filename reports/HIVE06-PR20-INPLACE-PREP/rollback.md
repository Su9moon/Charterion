# Rollback boundary

This task makes no live changes and supplies no switch/rollback script. There is no installed state to roll back. A candidate is an inert external directory; preserve failed/partial output for local review and select a different new outDir for a later attempt. The tool never cleans or deletes caller files.

Any later live change requires a separate reviewed procedure after the README evidence gates are satisfied. Keep old exact artifacts, root-derived identity, actual Host registration reference, actual loaded extension path and supported reversible reload plan. Code rollback cannot establish SQLite backward compatibility or restore lost Chrome storage.

Never terminate the current Kernel to release DB locks under this task. Never copy the locked DB/WAL/SHM as a purported consistent backup. An independently authorized, actual supported consistent-backup and restore rehearsal must establish recoverability first. Account for events written after any snapshot; do not discard newer attempts/events to force a rollback. Preserve existing bindings, locks, sessions and profiles. If schema/storage/ownership or provenance is unknown, remain BLOCKED.
